# 论文精读模块

来源：https://github.com/skJack/kelip-paper-reading 。本模块使用与模型无关的讲解流程，
仅在用户明确要求精读、逐节讲解或使用本模块时由 `research-workflow` 加载；
许可见本目录 `LICENSE`（MIT）。检索、下载、归档和普通论文问答完成后结束，
不能因为材料已准备好或目录存在而启动本流程。

完整精读保留七站，一站可分多轮；生物学问题与 AI 方法沿同一条主线相互解释：

```
1 动机与生物学问题 -> 2 方法架构 -> 3 训练与目标 -> 4 数据与样本
-> 5 信息流 -> 6 具体例子走一遍 -> 7 实验、证据、局限与研究空白
```

不按 AI / 生物学标签划分路线。计算表示、训练目标和模块设计要说明它们
服务于哪个生物学问题；生物学假设、数据获取和实验设计也要说明它们怎样
约束方法与结论。信息流与具体演算不能被背景介绍取代；证据核对贯穿七站。
实际没有训练的论文，第 3 站讲分析目标与方法，不补造模型或实验。

以下规矩贯穿全程：

- **论文图要随讲解显示。** 讲到哪张论文图，就在同一条讲解回复使用宿主支持的
  图片嵌入或原生附件先显示该图，再对着图讲；最终讲解也须保留相应展示。
  助手的图片查看工具不等于用户已看到图片，打印 base64 或写「看上面的图」也不能
  替代展示。没有展示能力时明确说明，并给实际原文页码及可用附件，不声称图已显示。
  具体准备、路径与发送方式见下方「图」一节。
- **带着读原文。** 先交代当前问题、原文位置与必要背景，再展开方法和结论。
- **用同一个样本看清转换。** 数据是什么、怎样进入方法、每一步变成什么、
  最后对应哪个研究对象，是讲解主线。关键操作用具体数值与转换前后的小图或矩阵。
  真实值、原图复算与教学设定明确区分；缺少中间结果就指出缺口。

## 在不同宿主中使用

下文 `<skill>` 指 `research-workflow` 根目录中的 `paper-reading/`，
即本 `guide.md` 的父目录，不是科研项目根目录。
从已加载根技能的实际位置设置 `SKILL_DIR`，再设置
`PAPER_READING_DIR="$SKILL_DIR/paper-reading"`。
下面的命令使用 Bash 语法，仅在有命令执行能力时运行；PowerShell 等宿主按自己的
变量和调用语法执行同一 Python 脚本及参数。脚本使用经检查可用的解释器，设置为
`PAPER_PYTHON`。优先复用当前机器的隔离环境；模块已有 `.venv/` 时，检查其中
实际解释器（Unix 为 `bin/python`，Windows 为 `Scripts/python.exe`），不复用从
其他机器复制来的虚拟环境。否则确认或建立隔离环境，安装本模块 requirements。
不仅检查 `import fitz`，还检查 `fitz.Rect(0, 0, 1, 1).get_area()` 返回 `1`。
requirements 排除有该接口回归的 PyMuPDF 1.26.5；官方记录见
https://pymupdf.readthedocs.io/en/latest/changes.html （1.26.6 的修复项 4742）。

遵守当前用户要求及项目指令。完整精读包含材料落盘、七站讲解与读完后的
笔记浓缩，不是只声明七站路线。用户指定只讲某一节时，仅补该节需要的材料；
指定完整讲完时按其要求合并阶段；通常一轮讲透当前站的一个问题，再接续未完内容。
图、公式及代码位置必须先检查实际材料，缺失信息明确标注，不能借样例补造。
七站保留各自的讲解目的，具体内容由实际论文决定，不强制存在模型、损失、
张量、代码或湿实验。每站连接研究对象、方法与证据，区分「不适用」「作者未提供」
和「尚未确认」，不能把不适用项一律写成未知或缺失。
本次明确要求准备精读目录和笔记，或此前已授权同一精读流程时，按授权落盘，
不要把通用的「不主动创建文档」解释成必须跳过用户要求的精读产物。
用户明确要求本次只在会话讲解、禁止落盘或离线时，尊重该限制并说明省略项；
宿主本身缺少文件写入、命令执行或联网能力时，也按实际能力处理：先用可读取的
全文讲解，列明尚未核查/未执行的材料步骤，不能把计划目录当实际产物。
需要某段补充材料才能判断时，请用户提供该部分；能力限制不能当成作者未公开。
无文件写入能力时在会话中记录当前停点与问答，结束时交付可复制的精读笔记正文。
后续会话需要用户重新提供这些记录，不假定模型有跨会话记忆。
有既有笔记时按本次授权更新，避免覆盖手工内容。画像仍只在明确要求保存时写入。

先定位科研项目根目录：以用户指定位置和适用项目指令为准，
从子目录进入时检查上层已有的 `related_work/` 和交接文件。
项目已有目标论文目录时复用该目录，不能依据新标题再造一份。
目录存在仅用于选择材料位置，不会自动启动精读或创建科研骨架。

## 第 0 步：准备并验收材料，再开讲

先复用已确认的论文目录。完整精读对以下各项逐一核对，缺什么就准备什么；
只有 PDF 能读，不代表精读材料已备齐。目录名沿用项目现有约定，
`papers/` 与 `related_work/` 不必相互改名，也不另建重复的论文目录。

```text
<论文目录>/
  paper.pdf       实际阅读版本的原文，保持原始字节
  source/         实际取得的 LaTeX 源码，记录来源与版本
  paper.tex       展开 input/include、去注释和参考文献，保留所需宏
  paper.txt       PDF 逐页文本；只有 XML 时注明其文本来源
  outline.md      章节、公式位置；有源码用 tex 行号，否则用文本行号/PDF 页码
  meta.json       书目、版本、材料状态、来源、官方仓库与提交
  supplements/    已取得并验证的补充方法、表格、图和 Source Data
  figures/        实际图表 PNG、index.md、index.json、_contact.png
  code/           已核对的官方代码浅克隆，或元数据指向既有代码位置
  精读笔记.md     阅读中记录已讲内容与问答，读完后在同一文件中浓缩
```

`source/`、`paper.tex` 和 `code/` 取决于作者实际公开内容；缺失时在
`meta.json` 记录检查日期、来源/查询、结果和原因，不创建空目录、伪造源码或
用 PDF 文本冒充 LaTeX。源码、代码下载失败与作者未提供是不同状态。

### 0.1 分别核对源码、补充材料与官方代码

- 本地 PDF 先从首页、DOI 链接和已有元数据确认论文身份及版本，再定位正式
  出版页面。同名预印本核对作者和版本，不能把参考文献的 DOI 当当前文章。
- 从用户链接、PDF 标识和已有元数据确认 arXiv ID 与版本。没有 ID 时，
  按准确标题、作者和 DOI 检索 arXiv，并核对作者/出版社/项目页的预印本入口。
  本地 PDF 文件名没有 arXiv ID，或文章来自 PubMed/出版社，都不等于没有源码。
  记录实际查询和返回范围；没找到匹配项不能声称已证明不存在 arXiv 版本。
  同时检查已确认的 bioRxiv/medRxiv 预印本、作者项目页和官方仓库是否提供
  写作源码。预印本 PDF 或 XML 不等于 LaTeX；有限检索没有结果时记录
  `not_located`，不把未公开源码当成材料准备失败，也不反复搜索同一组词。
- 找到匹配 arXiv 版本后实际尝试获取 e-print 源码，并检查响应是源码包、
  单个 tex、PDF-only 还是获取失败。有源码才生成 `paper.tex`，核对展开后的
  公式、表格和宏。源码与当前 PDF 版本不同或对应关系未确认时，明确标注，
  以当前 PDF 核对结论、公式和表格，不把预印本源码当正式版原文。
- 补充材料独立检查，不等待 LaTeX。从正文引用和出版社的 Supplementary
  Information、Supporting Information、Source Data 等栏目列出附件及其内容。
  核对补充方法、实验细节、表格和数据附件，不以正文包含 Extended Data 或
  Reporting Summary 代替独立附件。精读需实际尝试取得这些材料，逐项验收。
- 网页检索工具返回 403、重定向或 Internal Error 时，接着用脚本的普通 HTTP
  请求读取已确认的出版页面并提取附件直链；仍失败且有浏览器工具时，在浏览器
  检查同一页面的实际下载入口。按页面中的真实链接获取，不猜测附件编号或地址。
  出版社失败后检查已确认的 PMC、预印本或作者仓库镜像，注明版本差异。
  同一入口有限重试，遇到登录或验证码交给用户，不绕过访问控制。
- 在 `meta.json` 的 `materials.supplements.items` 保留每项的名称/内容、来源页、
  `reference`、实际 `url`、本地文件和验证结果。状态区分 `not_checked`、
  `identified_not_downloaded`、`identity_unresolved`、`failed`/`access_failed`、`available`、`not_located`；
  汇总可为 `partial`。失败写明所用入口、原始错误和已尝试的替代入口。
  已查页面未列出与网页访问失败是两种结果，均不能宣称作者没有提供。
- 从论文、作者项目页和仓库作者核对官方代码，排除第三方复现。已确认且
  当前任务允许网络时，实际浅克隆，不能停留在给 GitHub 链接或在线读几段代码。
  完整精读不默认使用 `--no-clone`；仅离线、用户禁止克隆或尚未确认官方来源时使用。

### 0.2 执行材料准备

确认官方仓库后，使用已有脚本准备材料，变量须先设为真实值：

```bash
cd "$PROJECT_DIR"
"$PAPER_PYTHON" "$PAPER_READING_DIR/scripts/fetch_paper.py" "$PAPER_TARGET" --dest "$PAPER_DIR" --code "$CODE_URL" --supplements
```

`PAPER_TARGET` 使用已核对版本的 arXiv ID、原文目标或已有论文目录。上面的
`CODE_URL` 必须已确认；确实未找到官方仓库时省略 `--code` 并暂用 `--no-clone`
准备其余材料，记录查找结果，不能把猜测的仓库交给脚本自动克隆。
本地/出版社目标不自动完成 arXiv 检索；生物医学分支也不会自动取得 LaTeX。
已有 `source/` 时按需调用脚本现有 `build_tex`、`build_outline` 功能，并检查结果，
不能因为某次运行没有生成 tex 就跳过来源核查，也不能杜撰命令行参数。

执行前设置 `PROJECT_DIR`、`PAPER_TARGET` 和 `PAPER_DIR` 的实际值。
用户指定位置时使用该位置；科研项目已有 `related_work/` 时，论文放入其下
已存在或按本次任务确定的论文目录。始终从项目根运行，便于官方代码进入
已有 `复现/<repo>/code`。不要为阅读任务主动创建 `复现/`；没有它时脚本
将代码放在论文目录的 `code/`，以 `meta.json` 的实际 `code_dir` 为准。
没有科研项目也能读论文，先确认保存位置，使用明确的 `--dest`。

依赖为 Python 3.9 或更高版本、PyMuPDF，克隆代码时还需 Git。
运行前用同一解释器检查 PyMuPDF 与上述矩形面积接口；若依赖缺失或不兼容，
在用户授权的隔离环境中运行
`"$PAPER_PYTHON" -m pip install -r "$PAPER_READING_DIR/requirements.txt"`，
不修改论文官方仓库的运行环境。本模块不要求特定 MCP 服务。

**先复用，再补材料。**完整精读按上面的清单验收，已完成项不重复下载；
续读时先检查上次材料状态，只补未完成项。不能因当前一站只需 PDF 就略过
尚未检查的源码、图表索引和代码。脚本会复用 PDF 与已有源码，但会重建 `paper.txt`、`paper.tex`、
`outline.md`、`meta.json` 和自动图表，不能把重跑说成只补缺的文件。
发现这些文件被手工整理时，不直接重跑整个流程；按需使用裁图脚本，
如确需重建手工修改文件，先说明具体影响并取得确认。
`--no-clone` 只禁止克隆代码，不能禁止网络访问；离线请求直接使用本地材料。

脚本接受 arXiv、PMID、PMCID、DOI、bioRxiv / medRxiv 链接、本地 PDF 和已有目录。
按实际来源取得 PDF 或 `paper.xml`，准备可用的文本、大纲与 PDF 图表；
arXiv 有源码时另有 `source/` 和拍平的 `paper.tex`。不保证全部可获取或固定耗时。
`--download-only` 仅保存原始材料与元数据，不准备精读派生文件；常规获取用此模式。
查看 `meta.json` 中 `materials` 的实际状态，只有摘要时不能继续讲成全文精读。
XML 全文按原始结构核对，公式、复杂表格优先查对应 PDF 或官方原文页面。
`--supplements` 从已有 DOI 或本地 PDF 首页唯一 DOI 候选定位出版社，核对页面 DOI；
自动候选还须与本地论文标题匹配，不能仅凭首页出现一个 DOI 就认定身份。核对后
解析实际附件链接，并保留 PMC XML/云端附件获取路径。它支持已验证的 Nature
附件结构及带补充材料标签的文件直链，不保证识别所有出版平台的动态下载组件；
未识别或访问失败时执行上面的浏览器/其他官方来源核查，而非立即结束获取。
PDF 验证能否打开，ZIP/XLSX/DOCX 检查容器与格式，拒绝空文件和 HTML 错误页。
只有完整下载且验证后才记为 `available`。大型原始数据集、受限资源或付费访问
遵守本次授权范围；若暂不获取，在对应条目写明原因，不伪装成全部备齐。

已有手工整理材料时，只补附件使用：

```bash
"$PAPER_PYTHON" "$PAPER_READING_DIR/scripts/fetch_paper.py" "$PAPER_DIR" --supplements-only
```

此模式只更新 `supplements/` 和 `meta.json`，不重建正文、大纲、图表或笔记，
不克隆代码。浏览器中核实的附件可补入上述 `items` 的 `reference`/`url` 后再运行；
已有文件先验证再复用，坏文件会报错并保留，不静默覆盖。没有唯一 DOI 时先人工
核实论文身份并写入元数据。退出码 `2` 表示附件未完整取得，继续查看逐项状态。

材料准备结束时明确说明哪些可用、哪些未定位、哪些下载失败。可以用已取得的
材料开始导读，但在进入依赖缺失补充方法/表格的讲解前须再次补取或明确证据边界，
不把“可以开始第一站”写成“全部材料已准备好”。
多个 PMC 云端版本必须按实际版本类型选定 `--pmc-version`。
PDF 必须能被 PyMuPDF 打开；源码、代码或图表缺失时记录实际原因与范围。
非空且没有脚本标记的人工 `figures/` 会保留，自动图改放 `figures-auto/`。
若 `figures-auto/` 也有手工图片，先检查 `index.json` 中的生成文件及本次输出
文件名，避免脚本重裁覆盖人工内容；使用实际图目录而不是固定假设 `figures/`。
已有 `精读笔记.md` 和其他笔记不由下载脚本处理，保留其内容。

### 0.3 验收实际产物

开讲前检查实际文件，并简短告知材料目录、已完成项和受限项。
这一步必须有文件或查询结果支撑，不能只列一个计划中的目录树：

- PDF 能打开且版本正确；`paper.txt` 有逐页标记，内容与 PDF 对应。
- 有源码时，`paper.tex` 非空且来自已标明版本的主文件；`outline.md` 的行号
  指向真实章节/公式。没有源码时，补全基于实际文本或 PDF 的章节与关键公式
  位置；自动大纲只有「没有书签」提示时，继续完善现有 `outline.md`。
- 图表 PNG 能打开，`index.md`/`index.json` 的图号、页码、caption 对应原文，
  `_contact.png` 汇总实际图表。无源码时，按正文补查关键图表的引用页或文本
  行号并补进现有索引，不把缺少 LaTeX 引用信息说成索引完整。
- `code/` 或 `meta.json` 指向的既有仓库是真实 Git checkout，核对
  `git -C "$CODE_DIR" remote get-url origin` 与 `git -C "$CODE_DIR" rev-parse HEAD`，
  把官方 URL、提交和实际目录写入元数据。非空目录不自动算克隆成功；已有
  仓库先核对来源，保留本地修改，不覆盖或擅自切换提交。

再做两件事：

1. **查看实际图目录中的 `_contact.png`（存在时）**（所有裁剪拼在一张图里）。标了「整页」或者裁坏的（混进正文、缺一半），在讲到它之前用 `crop.py` 修好。
2. **核对代码来源**：脚本识别的仓库只是候选，须用作者、论文或官方项目页确认。
   尚未确认时使用 `--no-clone` 只备论文材料；没找到时再检索方法名和官方代码，
   确认后完成浅克隆与元数据更新，不能把这个临时状态当完整精读的默认结束点。
   已确认且允许重建派生文件时，可运行
   `"$PAPER_PYTHON" "$PAPER_READING_DIR/scripts/fetch_paper.py" "$PAPER_DIR" --code "$CODE_URL"`；
   有手工派生文件时只浅克隆已确认的仓库到本次确定的代码目录，不重跑材料流程。
   经检查仍无可取得的官方代码，记录原因后继续讲解，明确代码核对的限制。

代码只用来读：不跑仓库里的脚本、不装依赖，除非用户要求。
数据、信息流和具体例子各站须使用已取得的代码：定位数据读取、字段定义、
预处理、模块调用与输出；优先检查仓库自带的小样本或用户已有数据，展示真实
字段、形状和可取得的样本值。数据说明和加载器只能证明定义，不能冒充已读取
真实数据；没有样本时写明缺口，教学数值单独标注。不因用户不想看代码就省略
助手的实现核对。不能为精读自动下载大数据集、权重或启动训练/API 分析。
按需核对公开样本、数据说明和处理代码；来源根据论文实际数据可为公开仓库、
数据附录、GEO、SRA、PDB、Hugging Face 等，不预设数据一定托管在某个平台。
若自行复算，明确区分实际结果与教学示意，不从统计量均值反推变量语义。

## 第 1 步：先自己读懂，再开口

用户要的是一个**已经读懂了**的人带着读，不是边翻边念。开讲前：

1. 读实际存在的元数据、大纲和图表索引，确认全文与补充材料范围。
2. 读正文：有 `paper.tex` 时可查公式与表格，但最终核对实际阅读版本；
   有 `paper.xml` 时按章节结构读，没有源码时结合 `paper.txt` 和 PDF。
   摘要、引言、方法及支撑主要结论的结果先读完；按问题补充 Methods、
   Supplementary Methods、数据说明与统计分析，不预设所有论文都是训练流程。
   长文可分段读取，但不能只读方法就宣称理解作者的结论与证据。
3. **查看关键的图**：teaser、方法总览图、数据图，用当前可用的图片/PDF 视觉读取能力检查实际图。caption 只说图想表达什么，不说哪个框在左边、箭头往哪走。只有文本读取能力时，仅根据文字解释并标明未检查图像，不推断位置和颜色。
4. 有代码时定位入口、数据处理、算法、forward、loss、推理与评价的调用链，
   检查生物学标识符怎样映射到模型行号、标签怎样形成、输出怎样回到研究对象。
   没有代码时核对原文的操作、分析与评价流程，不把推测写成实现事实。
5. 按需读本模块中已有的 `profile.md`（用户背景、熟什么不熟什么、喜欢什么例子），没有就跳过。
   读过论文、下载过材料或会编程不代表掌握当前概念。用户要求精读时仍按学习需求
   铺垫，不因阅读记录推断其想跳站；已明确熟悉的内容简述，指定跳站则照办。
6. 任务允许写笔记时，在论文目录中创建或更新 `精读笔记.md`（模板 `references/notes-template.md`），写好「基本情况」和「导读地图」：
   每站讲什么、用哪张图、在 paper.tex 哪几行、对应代码哪个文件。地图是给你自己用的路线，不整张贴给用户。

## 第 2 步：开场——基本情况，然后直接进第 1 站

第一条回复先给坐标，再讲内容（实测反馈：「首先介绍一下它的机构……先介绍基本情况，然后再说它的设计细节」）：

**基本情况**（不超过 6 行）
- 谁做的（机构从 PDF 第一页读；有的期刊模板不印，就去 paper.tex 的 `\author` / `\affiliation` 找）、什么时候、发在哪
- 一句话：研究问题、主要贡献及证据类型；计算论文再说明输入与输出
- 开源情况：代码 / 权重 / 数据，各开没开
- 材料放在哪（一行路径）
- 路线一行：按该论文实际方法、图表、公式、实验和代码填写，不套用示例编号

然后直接讲第 1 站，讲完按「每一站怎么收尾」结束。

## 每轮如何带着读

按「接上前文的问题 -> 原文定位与短引用/概括 -> 必要背景 -> 逐步拆解与具体操作
-> 回到原文解释证据」组织当前内容，不机械输出五个标题。短引用须核对原文并翻译，
概括明确标注，给章节、页码或行号；不能把助手概括加引号冒充原文。
新案例、新方法和新术语出现时，补上理解当前推理所需的背景，不只解释名词。
例如先讲为什么必须区分细胞来源，再引入单细胞分析；不要先堆结果再等用户追问。
背景只服务当前问题，随后落到输入、操作和输出；生物学、统计与 AI 概念同样处理。

开讲时选定可追溯的样本/候选/任务作为贯穿对象，在架构与训练站预告其输入输出，
第 4 站展开原始数据，第 5 站跟踪中间表示，第 6 站串起关键计算。沿用标识与变量，
切换案例要说明原因。全网络或多样本方法先解释共享上下文，不能把单一样本误讲成
完整模型输入。没有真实逐行数据时，以论文案例跟踪已知接口；独立教学演算只解释
已标明的局部操作，不把分别设定的数值拼成一次真实前向运行。

## 七站各讲什么

`references/examples.md` 用 KSHL-PC 论文贯穿七站，示范蛋白复合物问题、
谱超图方法、信息流与实验论证怎样一起讲具体。按当前站点读对应章节，
借鉴解释深度与组织方式，不把该论文的对象、维度、阈值和结论套到其他论文。
示例区分原文事实、固定提交中的实现、教学演算和待检验设想；始终核对
当前阅读版本的图、公式、代码位置与材料范围。

### 1 动机与生物学问题

讲完用户能一句话说出：**要解决什么问题、以前的做法卡在哪、作者押注的关键想法**。

1. 研究问题是什么，用论文实际对象和场景说明；预测、解释或干预什么。
2. 已有方法或知识卡在哪里，区分作者的论述与已被证据支持的不足。
3. 关键想法、机制假设或方法贡献；解释表示与学习目标怎样服务生物学问题，
   保留、压缩或忽略哪些关系，用什么证据检验。预测任务与应用愿景分别说清。
4. 举一个例子把问题讲实。
5. 发 teaser 图（通常是图 1），先说这张图是什么、每块在讲什么。

去掉论文的故事性和推销腔（"holds tremendous promise"），直接说它干了什么——实测反馈：「有点太绕了，能不能先去除他的故事性，直接先告诉我他是咋办的」。

### 2 方法架构

讲完用户能对着图指出方法各部分，或研究对象、分组、干预、测量和对照关系。

1. 先发总览图，第一段只讲「这张图是什么」：分几块、怎么读（从左到右？虚线、颜色代表什么？）、哪几个框其实是同一个网络。
2. 交代实际输入、输出、维度、单位、标识符、标签和任务；蛋白、细胞或患者
   的表征不等于复合物、组织或队列的判别结果。采集、分组、干预和测量影响
   方法解释时一起讲。时序或在线系统才讲时间与频率，不补造模型接口。
3. 按数据流动的顺序逐个模块讲：它是什么（从哪个预训练模型来、多大、训不训）、吃什么吐什么（形状说个大概）、
   **为什么要有它**——连回生物学假设，再比较最简单的替代方法。
4. 模块表写输入输出、作用、训练状态与证据位置；固定预处理、数值分解、
   预训练模型和本次训练参数分别写清。参数量和配置未经核对不填写。
5. 图太密就把正在讲的那一块裁出来单独发（见「图」一节）。
6. 用户明确熟悉的相近模型可对比一句；仅有读过的记录不能替代当前概念的解释。

这一站只讲结构。损失函数和训练流程留给 3，信息流的细节留给 5。

### 3 训练与目标

讲清实际目标、阶段、数据和参数更新，以及这些目标与最终生物学问题
相隔哪些步骤；变量、测量和统计分析怎样检验假设。只讲实际公式和代码。

1. 先定位原文的训练/分析段落，说明当前输入、要得到的输出和为什么需要这个目标；再介绍损失或测量。
2. 再给公式（写法见「公式」一节），逐个符号解释，然后代一组小数字算一遍。
3. 解释作者为何选择该目标、实验或分析方法；替代方案的比较依据不足时标明推断。
4. 训练流程：阶段一 -> 阶段二 -> …，每阶段写清数据、冻结 / 更新哪些部分、步数 / batch / 算力、关键 trick。
5. 训练和推理不一样的地方点一句（推理要去噪 10 步、要 KV cache……），细节留给 5。
6. 有代码就给 loss 的位置（`文件:行`）和那几行，逐行说；**代码和论文对不上的地方要指出来**（时间约定反过来、多了一项正则）。
7. 沿贯穿样本标出输入、预测、标签进入损失的位置及参数更新范围，说明优化器
   怎样利用梯度更新参数；区分可训练参数、临时激活与预先计算的固定特征。
   多阶段训练分别标明更新与冻结部分，再说明推理时哪些数据和标签不再需要。
   核对梯度和实际优化器，不因摘要写「端到端」就把固定特征讲成可训练参数。
   重建损失或预测损失降低不能证明生物机制成立。

无学习过程时讲操作、测量、对照、重复、分析方法与参数；
不要为不存在的模型写空训练流程，也不因研究对象是生物学就略过实际训练。

### 4 数据与样本

先承接研究问题，定位原文的数据段落，再打开一条真实记录；解释字段和一次关键
转换后再讲规模。样本不可得时明确仅有定义，教学数字不能充当实际读取的证据。
沿「磁盘文件/原始记录 -> 加载器输出 -> 预处理 -> 批次/模型实参」核对格式、
字段、数值、类型与单位，指出标签单独存放还是如何参与输入；非模型研究使用实际
分析接口。对张量逐轴解释对象与顺序，补位、掩码、图批次等按真实实现说明。
保留原对象 ID 与索引的对应，确保输出可以还原到蛋白、细胞、分子或患者。

1. 按原文解释观察单位：患者、动物、组织、细胞、序列、分子或其他实际对象。
   表格写字段、形状、单位、标签定义及可追溯样本值，不要求动作或本体状态。
2. 解释采集、质控、预处理和实际计算表示；训练/测试划分与泛化目标对应。
   按研究检查患者、实验批次、分子骨架或序列相似性造成的依赖和泄漏，
   不能把所有研究都规定为同一种划分策略。
3. 讲规模与来源、纳入排除、标签如何产生、标注和数据可用性。
   区分技术重复、独立生物学重复和样本数，适用时解释批次与混杂。
4. 在关键操作处展示同一数据转换前后的数值与形状，按下方「数据转换的可视化」执行；数据来源与可用性照实说明。
5. 区分一条原始记录、一个模型输入和一个评价样本；图研究区分节点、边、
   超边、候选集合与标签。RNA 表达、蛋白丰度、定位注释、物理互作和复合物
   成员关系不可互相替代，说明测量与代理特征的距离。
6. 解释负样本的生物学含义，随机负样本不等于实验确认的非复合物。
   共享整张网络的传导设置与新对象的归纳设置分别说明，不见共享特征就断言
   泄漏，也不把随机样本划分当跨物种泛化证明。随机种子和折数不算生物学重复。

字段和形状优先从代码的 dataset / transform / config 里读——论文常常写不全。例子值能用真的就用真的：
数据没公开时，仓库常带公开的示例数据集和归一化统计量，读一帧出来，把每一步变换用真实数值算一遍——
变量语义从字段定义及变换代码核对，不能仅凭数值大小确定。用了编的示意数要标「示意」。
论文和代码都没有的，就说「没写」，不要编。

### 5 信息流

保留独立站点，从原始研究对象跟到输出，解释每一步表示与生物学含义，
再接到实际评价、测量或实验及支持的结论；不能只讲机制背景而省略计算流。

1. 画一张文字流程图（代码块），箭头上标形状和次数：

   ```
   原始研究对象 -> 预处理/表示 -> 方法各模块 -> 对象级输出
   -> 样本/集合级输出 -> 筛选或评价 -> 生物学证据与结论边界
   ```

2. 分清哪些只算一次、哪些要循环、哪些结果被丢掉。
3. 分开说明训练与推理；存在差异时分别画流。训练标出标签、损失和参数更新，
   推理标出固定参数、可用输入及输出后处理。输出索引要追溯到原对象及其单位，
   区分原始分数、阈值判断、排序与最终报告；分数不自动是校准概率。
4. 机器人 / 在线系统补上时间：控制频率、一个动作块多长、一次推理多久、执行几步再推一次。
5. 对机制论述区分观察关联、干预效应与因果机制；明确哪些环节仍是解释或假设。
6. 标清标签进入哪里、梯度回到哪里、缓存何时复用；超边是建模假设，
   分类分数也不自动是经校准的实验真实性概率。固定特征不随候选重新训练。

对关键模块逐步回答：现在有什么、为什么做这一步、实际操作是什么、变成什么、
各轴/字段现在代表什么。不能用「编码、融合、预测」三个词跳过内部转换。
在有官方代码时对应固定提交的入口、加载、变换、forward/工具调用及后处理；
用户不想看代码时仍核对实现，以数值动作讲解。只读分析、实际执行和教学演算
分别标明。材料、依赖与授权允许小样本执行时，检查关键中间值和形状；精读不自动
授权训练、付费 API、全量运行或大数据下载，无法执行就保留未验证环节。
无训练的智能体系统跟踪实际请求、工具参数、返回字段、文件和反馈状态，不硬套张量。

### 6 具体例子走一遍

最重要的一站：前面每站都「懂了」，走一遍才是真的看见它怎么跑。实测里最常见的请求就是：「举一个例子，信息流走一走，配合代码」。

1. **沿用贯穿对象**：接着前几站已经使用的样本、候选或任务讲，不重新另选例子。
   尚未选定时，用户已指定对象就直接使用，否则优先选论文公开且可追溯的案例。只有选择确实影响讲解且无法确定时才问；没有画像
   不构成提问前置条件。用户在别站插话要例子时直接用论文自己的任务。
2. 计算方法可缩小规模，逐项说明保留了什么、省略了什么，再核对真实配置；
   生物学研究可走一条实际样本处理或实验链。教学数字不能冒充实验观察，
   缩小规模也不保证所有算法或统计性质保持不变；核对秩、采样等前置条件，
   不能声称仅换数字后原程序就能运行。真实案例与教学演算分别标注，不能
   给真实蛋白补造嵌入、GO 注释、表达量、预测分数或实验结果。
3. **按实际流程走**，每一步：现在有什么（对象、具体数值 / 形状）-> 做了什么
   -> 变成什么 -> 生物学上意味着什么。有代码就标固定版本的 `文件:行`
   与 3-10 行关键代码；无实际数据的中间步骤说明缺口，不冒充完整复现。
4. 关键的那一步单独用「这一刻发生了什么，用大白话说」再讲一遍。
5. 多轮的系统（机器人、自回归）至少走两轮：t=0 第一次调用 -> t=1（状态变了、缓存里多了什么、什么被丢掉）-> 之后的稳态循环。
6. 最后一行串起该论文实际计算、实验或分析链条。
7. 关键转换用小矩阵或数组展示前后变化，圈出正在计算的值；循环才用时间轴。
   图只帮助看清当前操作，不额外复制一套概念流程。具体规则见下方可视化一节。

具体程度参考 `references/examples.md` 第 6 节：从图 1 的 10 个示意节点
写出关联矩阵、复算归一化，再解释谱滤波、知识特征与集合评分；另用原文
POLA1/PRIM1/PRIM2/POLD3 案例连接真实推断与待完成验证。至少交代对象标识、
原始输入、逐步操作、中间表示、输出含义与验证方式，不以「融合后预测」收尾。

一次回复放不下（超过三屏）就拆开：这一轮走完 t=0，结尾问「要不要接着看第二轮和之后的循环？」。

用户说「不用给我讲代码」时：有相关代码可读它核对例子，只是不贴代码；
无代码研究核对原文方法、附录与实际实验材料，不强行检索一个模型仓库。
实测反馈：「对着代码，你不用给我讲具体代码怎么做的，但是你要看到代码之后，确切的给我举一个例子」。

### 7 实验、证据、局限与研究空白

完整精读必须讲支撑主要结论的结果与局限，不放在可选项里。
随对应站点核对对照、指标、效应量、不确定性、独立验证与证据范围；
适用时说明统计方法、多重检验和湿实验验证，不要求每篇都具备同样的实验。
每项实验对应一个主张，区分分类、集合恢复、跨对象迁移与机制验证；消融
讲清移除/保留内容和实际下降，不能由性能贡献直接证明生物学因果机制。
核对输入知识与验证资料是否同源；注释、结构预测、关联和干预证据分别支持
到哪一层。图表或指标矛盾给出处与复算，不擅自修成一致数字。
区分预测表现、观察关联与机制性结论；作者未做的验证不能补成已完成。
按实际方法说明训练与推理资源、实验条件及可复现性。
研究空白按「已有证据 -> 未回答的具体生物学问题 -> 可检验假设 -> 所需数据 /
方法变化 -> 对照、读出与失败判据」提出，避免泛泛建议换网络或增加组学。
相关实验设计区分作者实际完成的实验与建议开展的实验。性能提升不能直接
升级为疾病机制、药物作用或临床有效性结论。
「现在」的情况（后续工作、是否被超越）要去搜，并写明是哪天查的。
当前地位与后续文献仅按需检索，本论文的实验、局限与研究空白仍是第 7 站。

## 每一站怎么收尾

简短收束当前问题，并说明下次接着讲什么。一站可以分多轮，记录具体停点与未完操作。
用户说「继续」「好」时接续当前未完内容；本站讲完才进入下一站。明确要求「下一站」
或跳站时遵从，并记下跳过部分。继续不是已掌握的证明，也不需要每段考试或反复确认。

完整精读结束前，助手按实际研究核对是否已经讲清：新样本怎样准备输入；关键中间表示的数值/形状/
语义如何变化；标签与参数更新在哪里；输出如何还原到研究对象；哪些环节已核实、
哪些仍缺材料。尚未讲解的回到相应站点补齐或注明待续，不把七个标题出现当成精读完成，
也不擅自断言用户已掌握。

**跳站**（「直接讲数据」）：直接跳。当前这一站要用到被跳过那站的东西时，开头用两三行补上最小的必要背景
（用当前论文实际变量说明）；6 可以顺路把 5 走掉。跳过之后，「下一站」推荐还没讲的站里编号最小的，
被跳过的放进岔路，用户随时能回去。

每轮围绕一个可讲透的问题组织，信息密集的站拆成多轮；不规定一轮必须覆盖整站。
信息流、演算和实验不能为压缩篇幅而省略；背景、图和文字也不要重复同一信息。

## 用户插话的时候

- **随时会被打断问问题**：先回答，再简短指出当前具体停点；仍有未讲完的操作就接着讲，不因答完插问自动跳站。
- **用户复述自己的理解**（「所以是不是……对吧」）：第一句先判对错——「对」/「基本对，差在 X」/「不对」——再补那一点。
- **「没懂」「太抽象」「太乱了」**：别把同样的话说得更长，换一种讲法，按这个顺序试：
  1 具体例子 + 真实数字 -> 2 缩到玩具尺寸一步步走 -> 3 先摆出「最朴素的做法」和它为什么不行，再说作者的设计 -> 4 日常比喻 + 一张「比喻 与 论文」对照表。
  换完还不懂，请用户指出卡在哪一句，只解释那一句。
- **卡在前置知识**（「我是强化学习小白」）：停下来用三五段讲清这个概念（是什么、一个例子、在这篇里扮演什么角色），再回到原来的位置。
- **要翻译**（「翻译一下引言」）：逐段翻，原文和译文对照着放，公式照「公式」一节的写法，不加自己的解读——要翻译的人通常想先自己理解，再来问。
- **问「这个和 X 有什么区别」**：先一句话说本质区别，再一张对照表（输入 / 输出 / 训练目标 / 数据 / 推理方式）。
- **要「整理成文档」**：更新已有精读笔记；尚未创建时使用模板建立，补齐用户问过的问题，给实际文件链接。

## 数据转换的可视化

展示数据本身怎样变化，不为每段增加概念关系图。讲到非直观的聚合、归一化、
拼接、补位/掩码、消息传递或池化时，选当前样本的一小块，展示「转换前的数组/
矩阵 -> 具体运算 -> 转换后的数组/矩阵」，至少逐项算清一个值。标出行列、单位、
形状及原对象 ID；只截取局部或缩减维度时说明范围。颜色、连线或框选服务于对应
关系，不改变数据含义；无需每一步都画图，简单操作一组数值即可。

优先使用真实样本与实际中间结果；不可得时用明确标注的教学数字演示局部运算，
保留真实接口与示意维度的区别。材料中的未知值继续保持未知，不为图形完整补数。
图前一句说明为什么要做这步，图后只解释关键变化；避免再用长表和文字重复整图。
静态小矩阵或并排数组足以说明时直接展示；交互确能帮助追踪步骤时再使用当前可用
可视化能力，不增加必需插件。生成图片时核对后在同条回复嵌入；交互内容用实际
支持的展示方式，笔记保留关键状态的数值/矩阵，不依赖会话专用交互才能复习。
参考 `references/examples.md` 第 6 节中的关联矩阵归一化和补位池化演算。

## 图：发出来，先说是什么，再对着讲

- **先准备可嵌入的实际图片文件。** 复用已核对的 PNG/JPEG；只有 PDF 时，
  先定位图所在的实际 PDF 页码，用已有 `crop.py` 保存到本次已授权的论文或
  输出目录。有宿主原生 PDF 裁图/导出能力时也可使用，仍须核对实际结果。
  不需要重跑下载流程，也不为发图创建笔记。以下变量执行前须设置
  为已确认的 PDF、页码和输出 PNG 的绝对路径，输出父目录须已存在：

  ```bash
  "$PAPER_PYTHON" "$PAPER_READING_DIR/scripts/crop.py" "$PDF_PATH" --page "$PDF_PAGE" -o "$FIGURE_PATH"
  ```

  先渲染整页核对位置，再按需要追加四个比例坐标裁出完整图；确认的整页图
  也可展示并标明页码。不要把图片转成 base64 打印到终端或普通文本输出，文本输出
  无法替代可展示的图片文件。
- **检查图片，再按宿主方式显示。** 使用可用的视觉读取能力核对实际内容、完整性
  和清晰度；未能检查时如实标明。根据宿主能力选择以下实际可用方式，不假定所有
  聊天界面都能读取助手机器上的路径：
  - 支持本地图片路径内联的界面（如 Codex）：使用 Markdown 图片语法及发送前
    验证存在的当前绝对路径，`![图 3：模型架构](/实际/论文目录/figures/fig-03.png)`；
    路径含空格时用 `![图 3：模型架构](</实际/论文目录/含空格的图 3.png>)`。
  - 支持原生图片附件或产物预览的界面：使用该宿主真实提供的图片附件/预览接口，
    同一回复配上图号、页码和讲解，不虚构附件 URI 或上传接口。
  - 仅支持远程图片的界面：只使用已核实且允许显示的实际图片 URL；未获授权不把
    本地论文或图片上传到外部图床。只有 PDF 链接时明确它是原文入口，不冒充图片。
  - 以上都不支持时：明确说明本轮无法内联该图，提供实际图号、PDF 页码及可用
    文件/附件入口；没有入口就给原文定位，不编造可点击地址。
  将示例或笔记中的相对路径解析为当前实际材料位置，替换占位路径；发送前检查
  文件存在且可读。项目目录移动或改名后，重新定位同一论文的实际目录，并核对
  图号及论文身份；不能继续沿用历史绝对路径，也不只凭同名文件断定是同一张图。
  `meta.json` 中的代码目录也应检查当前实际位置，保留真实来源与提交信息。
  保存到笔记的图片路径优先相对于笔记，便于随论文目录移动；历史聊天中的绝对
  路径不会自动更新，需在当前回复重新展示，不擅自改名目录或创建兼容软链接。
  不用 `file://`、普通文件链接或代码块代替图片语法/原生图片展示。
- **发送前核对图解与展示一一对应。** 每张本轮解释的论文图都应有同一回复
  中的图片展示，紧接着才写「这张图」的讲解。最终回复重述图解时也保留该图，
  不能因工具已查看或进度消息已展示而省略。没有取得图片或实际显示渠道
  明确不支持内联时，如实说明原因并给可用链接；不能声称「上面已展示」。
- **发图后的第一段讲「这张图是什么」**：几块、怎么读、颜色和虚线的意思。然后才讲机制。
- **用位置指代**：「左边三个 ViT」「右上角的 a_t … a_{t+H}」，让用户的视线跟得上。
- **图太密就放大**：先用 `"$PAPER_PYTHON" "$PAPER_READING_DIR/scripts/crop.py" "$FIGURE_PATH" --grid` 看刻度（小元素可用 `--step 0.05`），再按确认的比例坐标运行同一脚本并用 `-o` 指定放大图的实际输出路径。
  要放大的块很小时，从 `paper.pdf` 那一页裁（`--page P`）比从 PNG 裁清楚。带刻度的图只给自己定坐标用，不发给用户。
- **一站两三张图就够**。表格也可以发图，但表里的数字从 `paper.tex` 读（PDF 抽出来的表常常错位）。
- **图裁坏了先修再发**：用同一裁图脚本对实际 `paper.pdf` 指定 `--page` 页码和 `--grid` 查看，再指定确认的四个比例坐标和输出路径。手工图另存，不覆盖原图。

## 公式：写成不用渲染也能读的样子

按当前宿主界面与用户要求选择写法，保留符号表和数值代入讲解：

- 支持公式渲染且用户允许时使用 LaTeX 数学表达式；不为普通数学解释创建 `.tex` 文件。
- 用户要求不用 Unicode 数学符号或公式无法渲染时，用 ASCII 代码块，
  如 `L(theta) = E[sum((v_theta(A_tau, o) - (epsilon - A))**2)]`，
  逐个解释下标、期望和求和，不把排版当成新增变量。
- 紧跟符号表：符号 | 是什么 | 形状 / 取值，再代一组明确标为示意的小数字。
  论文数据、示意数字、实际代码计算结果分开说明。
- 必须核对原式时，从 PDF 上裁下来显示：在大纲和逐页文本中定位，
  用 `"$PAPER_PYTHON" "$PAPER_READING_DIR/scripts/crop.py"` 指定真实页码与区域。

## 说话方式

- 跟用户用同一种语言讲；术语按当前论文领域选取，首次出现附简明解释。不自造术语。
- 开头明确本轮要解决的问题，先给原文与必要背景，再讲操作和结论；熟悉内容简述，陌生内容补上推理中间步骤。
- 区分三种来源并标出来：论文写的 / 代码里看到的 / 我推测的。论文没写的不要编；代码和论文不一致时两边都说。
- 数字带当前材料出处（图、表、附录、页码或实际代码文件和行号）。
- 比喻只用日常物理场景（下棋、开车、考试抄答案），不用拟人小故事（「模型就像一个厨师……」），用完给对照表落回论文。

## 精读笔记：阅读中积累，读完后浓缩

完整精读按授权维护论文目录中的同一份 `精读笔记.md`（模板
`references/notes-template.md`）。已有其他笔记不覆盖；用户明确只要会话讲解
或禁止落盘时，跳过写入；宿主无写入能力时交付可复制正文并说明尚未保存。
不要为进度、问答和最终总结再创建多份文档。

- 开讲前写好「基本情况」、实际材料状态和「导读地图」，标明「精读进行中」。
- 每轮结束更新实际停点；阶段性整理到原有站点中：原文位置、必要概念、贯穿样本
  来源、关键转换前后数值与语义、图（相对路径）、公式及代码定位，不原样粘贴回复。
- 用户问过的问题和最后的答案记进「问答」：问过的问题本身就是最好的复习提纲，也是以后讲给别人听的骨架。
- 本轮记录合并写入同一笔记，不为分轮另建文件。
- 第 7 站已讲完且本轮问题已处理，或用户明确说「读完/结束并整理」时，
  在同一文件中去重浓缩：保留研究问题与贡献、关键图和公式、实际代码与数据
  信息流、贯穿样本的输入到输出及训练更新范围、关键转换示意、证据与局限、
  可检验研究空白，以及用户问答中真正的卡点与仍未核实的环节。保留来源定位与必要数字，删除重复讲解、聊天套话和未填模板占位项。
- 完整七站已读才标记「精读完成」；用户提前结束则标记实际已读范围。
  保存后检查图片相对路径和代码定位，按宿主能力提供真实文件链接或附件。
  没有实际生成文件时只交付正文，不伪造文件路径或下载链接。

## 脚本速查

脚本都在 `<skill>/scripts/`，即 `$PAPER_READING_DIR/scripts/`；以 `"$PAPER_PYTHON"` 运行，不能直接执行裸文件路径。下表的相对路径（`figures/…`、`paper.pdf`）指论文目录，在论文目录里跑或者写绝对路径。

| 命令 | 干什么 |
|---|---|
| `fetch_paper.py <链接/ID/PDF/目录> [--dest D \| --root R] [--code URL] [--code-dir D] [--no-clone] [--supplements]` | 获取材料；会重建派生材料，重跑前按第 0 步检查。精读加 `--supplements` 查找并下载附件 |
| `fetch_paper.py <已有论文目录> --supplements-only` | 仅补充附件和元数据，保留正文、大纲、图表、代码与笔记 |
| `extract_figures.py <论文目录> [--dpi N]` | 重新裁所有图表 |
| `crop.py <图或 paper.pdf> [--page N] [--grid [--step 0.05]] [x0 y0 x1 y1] -o 输出.png` | 放大局部 / 裁公式 / 重裁坏图（坐标是 0–1 的比例） |

论文目录：`paper.pdf` · `source/` · `paper.tex` · `paper.txt` · `outline.md` · `meta.json` ·
`figures/`（`fig-NN.png` `tab-NN.png` `index.md` `_contact.png`）· `supplements/` · `code/`（或 `复现/<repo>/code`）· `精读笔记.md`
